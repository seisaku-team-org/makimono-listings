# 秘書スキル: 会食先リストアップ

会食日程リストアップの業務マニュアルを参照しつつ、店候補は Web 検索と過去履歴 Sheet から導く。

## 関連リソース
| 項目 | 値 |
|---|---|
| 会食履歴 Sheet | `<MEAL_HISTORY_SHEET_ID>`（過去の会食先・評価・次回利用可否を記録） |
| 既定の時間帯 | 18-20時の2時間、移動含め 17-21時で日程確保 |

## ヒアリング項目（揃ってない要素は聞く）
最低限「場所」「人数」「日付（候補）」を最初に確定し、足りなければ追加質問:
| 項目 | 必須/任意 | 例 |
|---|---|---|
| **場所エリア** | 必須 | 「東京・銀座」「大阪・北新地」「梅田徒歩圏」「会場最寄り」 |
| **人数** | 必須 | 「主催者含めて3名」「6名」 |
| **日付** | 推奨 | 「来週木曜」「11/15」「未定」 |
| **予算/人** | 推奨 | 「1.5万」「3万」「お任せ」 |
| **料理ジャンル** | 任意 | 「日本料理」「焼肉」「鉄板」「中華」「フレンチ」「お任せ」 |
| **目的** | 任意 | 「契約後の御礼」「初顔合わせ」「成約祝い」「お疲れさま」 |
| **参加者の特性** | 任意 | 「アレルギー: 蕎麦」「お酒苦手な方含む」「先方経営者60代」「女性比率高い」「外国人含む」 |
| **個室希望** | 任意 | 「個室必須」「半個室可」 |
| **雰囲気** | 任意 | 「落ち着いた」「賑やか」「カジュアル」「フォーマル」 |

## リサーチ手順
1. **会食履歴 Sheet を確認** — 履歴シートを読む
   - 同じエリア＋同じ目的の過去案件があれば候補に含める（評価 4 以上、次回利用 OK のもの優先）
   - 同一参加者と既に行った店は避ける（メモ列参照）
2. **Web 検索** — 「{エリア} {ジャンル} {予算帯} 個室 接待」等のキーワード
   - グルメサイト・公式サイト等が出てきたら情報整理
   - 接待・会食用途の店リスト記事（「銀座 接待 個室」など）も有効
3. **裏取り** — 候補ごとに必ず:
   - 公式 URL or グルメサイト URL を確認
   - **Google Maps 検索URL** を生成: `https://www.google.com/maps/search/?api=1&query=` + URL エンコードした「店名 エリア」
   - 営業時間・定休日・予約方法を確認

## 出力フォーマット
```
【会食先候補】
日程: 6月12日(木) 19:00–21:00
場所: 東京・銀座
人数: 4名
予算: 2-2.5万円/人

1. ◯◯（鮨）★★★★☆
   https://www.google.com/maps/search/?api=1&query=%E2%97%AF%E2%97%AF+%E9%8A%80%E5%BA%A7
   グルメサイト: https://.../
   個室4名、予算2万円、徒歩5分、過去利用なし。落ち着いた雰囲気で接待向き。

2. △△（割烹）★★★★★
   https://www.google.com/maps/search/?api=1&query=...
   履歴: 2025-11-10 に同じエリアで利用、評価★5、「次回OK」フラグ有
```
過去履歴を引用する場合は **必ず日付と評価を明示**。

## 履歴への追加
会食実施後、または「△△の店、良かった」と言われた時に、会食履歴 Sheet への追記案を出す:
```
履歴に追記しますか？
- 日付: 2026-06-12
- 店: ◯◯（銀座・鮨）
- 場所: https://www.google.com/maps/search/?api=1&query=...
- 人数: 4 / 予算: 2万 / 評価: 4
- 参加者: A社 ご担当者
- メモ: 個室、応対が良い、次回OK
```
Sheet 直接書き換えができないコネクタでは、コピペ用テキストを提示して手動 append を依頼する。

## 会食日程の取り方
時間帯の既定: **18時〜20時の2時間**、移動含め **17時〜21時で空き**。
カレンダー空き探しは日程調整スキル（場所考慮あり）を呼ぶ。

## やってはいけない
- グルメサイト等を見ずに「だいたいこういう店」と憶測で店名を作らない（必ず実在確認）
- Google Maps URL を返すとき、店名を URL エンコードせずに日本語生のまま `query=` 後ろに置かない（一部ブラウザで化ける）
- 履歴 Sheet にある「次回利用NG」の店を再提案しない
- アレルギー情報を聞いた後にそれを無視した店を提案しない
- 「銀座 高級 個室」みたいな広すぎる Maps URL を出さない（**店名特定済みの URL** を出す）

## やってよいこと
- 候補ごとに「強み」「弱み」を1行ずつ
- 主催者の好み（過去履歴の傾向から推定）を反映
- 季節メニュー・予算上限を考慮
- 駐車場・最寄り駅・タクシー乗り場の有無を補足
